[#expose-a-remote-module]
= Expose a Remote Module

Every application integrated with OneCX must expose itself to the shell via Module Federation, so the shell can dynamically load it at runtime. This page covers the requirements and setup steps for both Angular and React applications.

[#overview]
== Overview

Content loading is triggered by route changes (for modules) or Slot Component display (for remote components). The content is loaded via the remote entry file (`remoteEntry.js`) configured in the bundler's Module Federation plugin. Regardless of technology, an application *must* expose a `remoteEntry.js` — see xref:documentation:docs-guides-ui:setup/required/platform-package-compatibility.adoc[Platform & Package Compatibility Requirements] for the full compatibility baseline.

It is recommended to build on `@module-federation/enhanced` (directly, or via `@nx/angular/module-federation` for Nx applications) and to also expose the `mf-manifest.json` file it produces, which contains metadata about the exposed modules and their dependencies and enables better integration and compatibility with the shell. See xref:documentation:onecx-docs-dev:shell-integration/shell-v3-migration.adoc#mf-manifest[Exposing mf-manifest.json file] for details.

[#angular-applications]
== Angular Applications

[#angular-webcomponent-method]
=== Webcomponent Method (Recommended)

This method uses Web Components *Custom Elements* to register content, allowing multiple frameworks and Angular versions to coexist in the shell. It is the recommended approach; the alternative "Angular expose method" (exposing an `NgModule` directly) limits the whole platform to a single Angular version and is not recommended.

There are two ways to expose an Angular application depending on what needs to be loaded by the shell:

* xref:documentation:docs-guides-ui:setup/required/expose-remote-module/module-approach.adoc[Module Approach] — expose a full Angular module, loaded on route activation.
* xref:documentation:docs-guides-ui:setup/required/expose-remote-module/component-approach.adoc[Component Approach] — expose a single component, loaded by a Slot Component.

[#react-applications]
== React Applications

React applications are turned into a Custom Element and exposed the same way, using `@onecx/react-webcomponents`.

[#react-vite-webcomponent]
=== Converting a React App into a Web Component

The `createViteAppWebComponent` function converts a React component or React app into a custom web component, relying on the browser's Custom Elements API and the `@r2wc/react-to-web-component` library.

[source,js]
----
const createViteAppWebComponent = (
  app: React.ComponentType,
  elementName: string
) => {
  // Implementation
};
----

* `app`: the React component to convert into a web component.
* `elementName`: the name of the custom element to register (e.g. `my-custom-element`).

.Example for a Vite App
[source,js]
----
import App from './app';
import { createViteAppWebComponent } from '@onecx/react-webcomponents';

createViteAppWebComponent(App, 'my-custom-app');
----

Expose the resulting entry point via Module Federation the same way as any other technology, with a `webpack.config.js` (or equivalent) that exposes `remoteEntry.js`:

[source,js]
----
const config = withModuleFederationPlugin({
  name: 'example-react-ui',
  filename: 'remoteEntry.js',
  exposes: {
    './ExampleApp': './src/main.tsx'
  },
})
----

See xref:documentation:docs-guides-ui:react/libraries/react-webcomponents.adoc[@onecx/react-webcomponents] for the full library reference, including routing helpers (`useAppHref`, `SyncedRouterProvider`) used once the app is loaded in the shell.
